## How strings are translated

- `agent-notes/scripts/i18n.py export` writes `agent-notes/i18n/source.json` (every key with English, Simplified Chinese,
  Japanese and a hint of where it shows). `agent-notes/i18n/TRANSLATE.md` is the brief: Microsoft Office's own terms for
  each language, placeholders kept, short ribbon labels, function names and codes kept, template content localized.
- Translations land as `agent-notes/i18n/out/<code>-NN.json`; `i18n.py verify <code>` checks them; `i18n.py merge <code>`
  writes `values-*/strings.xml` in the default file's order (attributes copied, escaping done); `i18n.py check` and the
  unit test `TranslationsTest` keep every language complete with the same placeholders.
- New strings from now on need all 18 languages: `add-strings.py` takes `{key: {code: text}}`.
- Machine translation by the model, following Office's terminology — a native review before release is advisable.

## Rounds

1. **Groundwork** (round 79): the 18-language `AppLanguage` and the Settings list (each language in its own name),
   `res/xml/locales_config.xml` for the system's per-app language setting, debug pseudo-locales (en-XA) for finding
   labels that do not fit, translation tooling and `TranslationsTest`; dates — Excel date formats (`FormatCode.Lang`
   for all 18, names from the platform's locale data), Word DATE fields (names and the default short date of the
   language; hangul no longer taken for Chinese), Word's Date and Time formats per language; a new document or workbook
   starts on Letter only where that is the norm (it was always Letter — wrong for Chinese and Japanese Word too).
2. **Translations merged** (round 79) for the 14 new languages; checked on the device (round 80: Home in de, ru, th, hi, ko;
   the six tabs the pseudo-locale found too wide in de and ru — all fit; big ribbon labels hyphenate per language);
   still to check: ribbons (22 tabs) and the
   most used dialogs, with the ribbon squeeze and label widths fixed where a language overflows.
3. **Spreadsheet numbers follow the language** (as Excel does with the system's settings) — a and b done in round 82, c and d in round 83, the dialogs' formulas (validation, conditional formatting, names) and Format Cells' currencies in round 84:
   a. display — the decimal and grouping symbols of format codes and the General format, in cells, the formula bar's
      values, charts, PDF export, the status bar's figures, Format Cells' samples;
   b. entry — 1,5 and 1.234,5 read as numbers where the decimal symbol is a comma; dates in the language's order
      (8.10.2026, 08/10/2026); percent and currency entries;
   c. formulas — shown and typed with the language's separators (`=ROUND(A1;2)`, `1,5`) and stored in the file as
      always (`ROUND(A1,2)`, `1.5`); function names stay English;
   d. currency — the currency button and Accounting format use the language's currency (€, ₩, R$, ₽, zł, ₺, ₫, ฿, Rp, ₹).
4. **Documents and slides** — round 85: a document in Korean, Thai, Hindi, Vietnamese, Russian, German, Chinese
   and Japanese keeps every character through docx and ODT, shows on the canvas and exports to PDF with each script's
   font (Noto Thai, Devanagari, CJK; LibreOffice renders the files the same); the Office theme (docx and pptx) names
   Word's fonts for Hangul, Thai and Devanagari; proofing checks each paragraph in its own language (`TextLanguage`:
   by script, and for Latin letters by common words and letters only one language uses) — German text is no longer
   checked against English when the spell checker has no German; Pages' table formulas read and write numbers with
   the language's symbols (=SUM(ABOVE) of 1.234,50 € and 2,5 is 1.237,00), the Formula dialog takes `=SUM(B2;C2)*1,5`
   and offers the language's currency picture; table sorting reads 1.234,5 and 16.10.2026 the language's way;
   lengths, row heights, crop percentages and chart data show the language's decimal symbol.
   Round 86: the home screen's templates are built and round-tripped in all 18 languages (`TemplatesTest`) and checked
   on the device in German and Korean; the plain Date format (Excel's built-in 14) and Date-time show the language's
   short date (15.10.2026, 10/15/2026, 2026/10/15, 2026-10-15) in the grid, status bar, Format Cells and PDF, CSV keeps
   ISO; right-aligned text runs on over empty cells to its left, as in Excel (the German invoice's "RECHNUNG").
   Round 88: Chinese characters take their paragraph's language's forms (`HanLocale`: kana make it Japanese, hangul
   Korean, Han alone the reader's language — Simplified Chinese in other apps) on the Pages canvas, in slide boxes and
   in the PDF (PICO Sans JP beside PICO Sans SC), where before Japanese text in a Chinese app drew in Chinese forms.
   Word picks by each run's language, which the model does not keep; the text tells instead.
5. **Instrumentation and screenshots in several languages**, and a native review list — round 87: the app and test
   APKs installed, the app's language set with `cmd locale set-app-locales`, and the suite run with `am instrument`
   (Gradle's connected task uninstalls the app and so drops the language); the tests take every label from the
   app's resources. `DeskFlowsTest` in German found that four suites typed into the title bar's search box (added in
   round 74, after the last full run) instead of the document — fixed in every language with `TestSupport.notSearch`.
   New workbooks and sheets are named as the language's Excel names them (Tabelle1, Feuil1, Hoja1, Лист1, 工作表1).
   The review packets for native speakers: `python3 tools/i18n/review.py` → `build/i18n-review/` (see
   `docs/i18n-review.md`).
